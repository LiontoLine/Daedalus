# 模型连接与凭证安全保存

适用于当前 macOS 桌面部署。其他系统的安全保存不可用时会明确报错；可使用临时连接或由受信任的启动环境提供凭证。

模型设置默认勾选「安全保存连接，重启后自动恢复」。填写一次并应用后，后端重启自动恢复模型连接。旧进程已丢失的内存密钥无法迁移，需要首次重新输入一次。系统若要求钥匙串授权，须由用户在 macOS 提示中处理。

## 保存边界

| 内容 | 保存位置 | 重启行为 |
| --- | --- | --- |
| API Key、连接参数摘要 | macOS 登录钥匙串的独立通用密码条目 | 创建客户端时读取，不通过 HTTP 返回 |
| 地址、模型、协议、角色、超时、兼容参数、密钥指纹和随机引用 | 工作区 `.model-settings/connections.json`，文件 0600、目录 0700 | 启动自动加载，界面显示来源 |
| 取消安全保存的连接 | 当前进程内存 | 下次启动恢复已保存连接或启动配置 |
| 环境变量方式 | 保存变量名，值仍由启动环境提供 | 不把环境变量值复制到普通文件 |

工作区路径的摘要划分钥匙串命名空间，各角色使用随机凭证引用。Keychain 请求通过 Python 标准库 ctypes 直接调用 Security.framework，不把密钥放进命令行、shell 历史或临时文件。条目不请求 iCloud 同步。项目没有自制加密密钥文件或明文回退机制。

## 调用与失败处理

钥匙串内同时保存凭证及完整连接参数的 SHA-256 摘要。创建客户端前校验绑定；地址、角色、协议、模型或兼容参数被改写后，旧凭证不能用于该配置。编辑时仅同地址、同协议并符合角色范围的连接可复用原密钥，换地址需重新提供。正常更换参数并安全保存会更新绑定。

批量保存先写新钥匙串条目，再原子替换公开配置，最后清理旧条目。写入或配置提交失败时清理本次新增条目，原运行配置保持有效。进程恰在提交前退出可能留下未引用的钥匙串条目；它不会成为生效连接，也不含在项目导出中。损坏配置可清除重建，已无法识别的旧引用不会猜测删除。

启动只加载公开参数，不读取所有密钥或发起模型调用。钥匙串锁定、拒绝授权、凭证缺失或绑定不符时，新客户端创建失败；不自动改用其他主机。已经创建的客户端持有其凭证快照，密钥轮换不破坏正在进行的调用。

「清除已保存连接」删除该工作区对应的钥匙串条目和设置。删除被拒绝时保留引用，便于解锁后重试。导出文件不含密钥和钥匙串引用；迁移到另一台电脑或另一工作区仍需重新配置凭证。备份项目数据库不等于备份系统钥匙串。

## 安全前提

后端与当前 macOS 用户会话受信任，系统钥匙串处于可访问状态。进程调用模型时必然在内存中使用密钥；钥匙串不能抵御已经控制此用户账户或后端进程的攻击者。默认保持回环监听；私有局域网访问须先启用独立的访问鉴权，但它不构成公网多租户安全保证。不要将访问登录与任务 Owner 审批混为一谈。

恢复模型连接不会恢复任务执行。服务启动仍只展示断点提醒，中断任务需要人工审查后明确继续。

## 维护与排障

离线测试通过注入的假凭证库覆盖重启恢复、协议角色、导出与磁盘内容、文件权限、配置篡改、批量失败回滚、钥匙串不可用和密钥轮换。它们不触碰真实 Keychain 或调用真实模型；平台集成仍需在受信任的正常用户会话中单独检查。

遇到钥匙串错误时，先检查系统是否允许当前后端访问条目，不要通过命令行打印凭证或改用明文文件绕过错误。清除连接前确认仍能重新取得密钥；迁移工作区后应重新配置，不要手工复制随机引用。

日志、数据库和导出虽然不应保存密钥值，仍可能包含仓库上下文、地址、模型名称等资料；分享前必须审查。秘密扫描与脱敏并不保证识别任意敏感信息，完整安全前提见 [安全策略](../SECURITY.md)。
