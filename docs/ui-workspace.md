# 本地任务工作区

Daedalus 的 Web UI 与 HTTP API 由同一后端提供，采用服务端模板与静态 JavaScript，不需要独立前端构建。启动步骤见 [项目首页](../README.md#启动本地-ui)，服务管理见 [终端与服务控制](service-control.md)。

## 四阶段工作流

首页 `/` 将一个任务的操作按顺序放在同一页面：

1. **提交任务**：选择可信 Git 仓库，描述目标与约束，回答需求澄清问题。新建入口不会自动选中历史任务。
2. **产出规划**：查看步骤、依赖、预期产物、验收标准与可修改范围，检查完整规格，再明确确认执行。规划不是已完成的代码。
3. **执行任务**：通过 DAG 查看节点与依赖，选择节点检查状态、改动、门禁、制品和历史；等待或升级状态需要相应操作，不能仅因图形显示完整就视为成功。
4. **审计与改进**：核对目标结论、代码改动与事件记录。目标偏离后可查看反馈及关联任务，现有迭代机制含首次最多三轮；不是无限自动修复承诺。

页面上方的流程导航用于阶段定位，已经产生的信息保留在本页。历史 `/planning/{run_id}`、`/execution/{run_id}` 和 `/audit/{run_id}` 入口使用相同工作流并定位相应阶段。

## DAG 与节点检查器

依赖关系来自冻结计划，节点状态来自后端投影。计划节点和已声明执行步骤应区分展示，不能把尚未执行的规划当作完成证据。

- 点击节点查看概览，逐层展开代码改动、门禁和历史；完整规格及签批按需展开。
- 可缩放、平移并选择节点。轮询更新尽量保留当前选择、选项卡、展开内容和未提交表单。
- 任务切换时更新各阶段内容，并拒绝让较慢的旧请求覆盖新任务。
- 缺失审查、评分或目标审计时明确显示缺失，不推断为通过。

页面只是事件与状态投影的查看入口，不是新的权威事实源；写入、审批与执行继续走现有应用服务。

## 其他入口

| 入口 | 用途 |
| --- | --- |
| `/runs` | 查找与筛选历史任务，查看概况并进入对应工作流 |
| `/operations` | 隔离、配置、指标、备份及恢复操作 |
| 页面「模型设置」 | 分配规划、编码和审查连接，导入导出配置及测试连接 |
| 「项目记忆与决策依据」 | 按项目保存确认资料、执行试查并查看近期检索引用 |
| 页面「服务」 | 记录下次提醒、保存断点并关闭或重启 |
| 页面「访问设置」 | 配置访问登录及受支持平台上的托管选项 |

模型操作详见 [模型设置](model-settings.md)，项目资料详见 [项目记忆](agentic-rag.md)。实际界面以当前后端版本为准；刷新页面不能替代加载新 Python 模块所需的服务重启。

## 安全与解释边界

- 运行本地 UI 不需要立即提供模型凭证；只有实际任务或连接测试才应按相应操作发送请求。
- 连接测试会真实调用所选模型，可能产生费用；任务调用还可能发送代码和检索上下文，需先确认资料允许外发。
- 登录、Owner 签批和恢复审查是不同控制，不能相互替代。启动、查看断点或保存审查备注均不自动继续任务。
- 审计页的展示有数量限制，完整记录需通过导出获取；导出可能包含敏感业务内容，不能默认公开。
- UI 状态、门禁结果和模型审查不构成形式化证明或安全保证。部署前阅读 [安全策略](../SECURITY.md)。

## 维护入口

实际页面实现位于 `src/daedalus/service/templates/`，交互逻辑与样式位于 `src/daedalus/service/static/`。评审应以真实服务页面和 API 为准，不依赖独立布局预览。相关回归应覆盖任务切换、慢响应、缺失历史记录、输入保留和拒绝路径；离线假响应检查不能替代平台浏览器与真实监听环境的单独验收。
