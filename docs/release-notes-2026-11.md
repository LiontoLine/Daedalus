# Daedalus 更新说明：对话工作台、逐路径验收与证据续修

公开源码包包含通用验收判定及配套回归。普通命令按退出码判定，要求原生收据的验收还需完整执行证据；公开检出无需私有维护脚本或研究数据。

本说明以现有 `Daedalus-main` 源码快照为主基线，并与此前交付的三份开发包逐文件对照。四份基线及本包均使用 Python 包版本 `0.1.0`；下列名称区分源码快照，不表示曾发布四个不同的 PyPI 版本。

## 与现有 Daedalus-main 的差异

现有 `Daedalus-main` 已有逐节点冻结预期、候选主干和隔离修复分支。本次不是重新引入这些机制，而是让用户可以从对话进入它们，让修复更早拿到可执行反馈，并让最终交付可核对。

| 场景 | Daedalus-main | 本次提交包 |
| --- | --- | --- |
| 新建任务 | 从独立任务表单进入需求与执行流程 | 对话为首页。发送目标后保留用户消息和澄清回答，生成可展开的规划预览；确认后才开始执行。 |
| 查找历史 | 通过任务入口和当前任务选择控件进入流程 | 左侧以已记录任务为来源，按目标、目标 ID 或运行 ID 搜索；点开先看状态、步骤进度、风险和交付摘要。 |
| 查看单个任务 | 各阶段沿同一工作流纵向展开 | 「对话与摘要 / 规划 / 执行 / 审计」一次显示一类内容；验收与规格、签批、交付记录、指标、近期活动可展开。审计内部可切换结果、差异、事件。 |
| 读 DAG | 按已冻结依赖展示计划和执行步骤 | 并行节点留出同层空间，跨层边绕开中间节点；选中节点突出直接依赖。执行图支持定位、平移、缩放，右侧检查器默认收起。 |
| 验收真实行为 | 有冻结预期和需求验收，通过或拒绝候选 | READY 预检可冻结完整用户路径：入口、状态变化、结果、变更与不变式。对同一内容树分别展示通过、未满足和未知。 |
| 候选失败 | 有界修复历史、隔离编辑及门禁复验 | 同一工作树可在读取、编辑、声明检查和修复之间继续；分叉点的已执行失败可在增量编辑后即时重验，下一条请求收到实际反例。 |
| 找出责任节点 | 结合失败预期和依赖找修复点 | v2 验收可指定具体 `repair_path`。整体验收存在实际失败且该路径唯一归属冻结节点时，按该节点发起隔离修复，并显示归属或歧义。 |
| 查看交付状态 | 有目标验收、审批及 Git 快进流程 | 同一执行、规格和提交的 Git 请求与完成收据决定是否显示已发布；审计通过、等待复核、发布待确认和冲突分别展示。 |

## 本次能力详解

### 1. 对话、历史和分面工作台

1. 首页选择 Git 仓库，描述目标及要保留的行为。**Enter** 发送，**Shift+Enter** 换行。发送只启动需求分析；澄清、规格预览和显式确认仍是执行前的步骤。
2. 点左侧历史先回到「对话与摘要」，不自动展开执行或审计数据。用上方按钮切换视图，老的 `/planning/{run_id}`、`/execution/{run_id}`、`/audit/{run_id}` 链接仍能直达。
3. 规划图突出所选节点的直接依赖；执行图节点同时展示执行状态和可用的预期状态。点节点打开检查器，在「总览 / 改动 / 门禁 / 记录」之间切换，可随时收起。
4. 看交付时先核对摘要，再展开原始验收、完整交付记录或一致性指标。窄屏将历史放在上方，可折叠；图画布在自身区域滚动。

入口实现：`workflow.html`、`_workflow_*.html`、`console.js`、`console.css`。操作详见[任务工作区](ui-workspace.md)。

### 2. 冻结验收及独立路径证据

- 同一份 v2 契约可以覆盖希望改变的行为和必须保留的行为，要求实际测试绑定到各自的路径。新行为在预检基线需能暴露缺失，保留行为须通过，才能生成 READY 收据。
- 网页、CLI 与直接任务 API 支持绑定 READY 收据。执行前核对目标、仓库、基线、范围与隔离策略；整题的行为检查在集成树执行，而不是在未集成的局部工作树猜结论。
- 编码和审查使用公开需求、对应路径状态及收据标识。普通审计查询及 JSONL/CSV 导出沿用公开投影；私有测试方法、输入和原生失败正文不靠提示传递。
- `repair_path` 将完整的集成行为失败归属到唯一声明同一路径的节点。只有审查疑点或没有可靠归属时，不把它当作已经执行的反例。

主要文件：`requirement_evidence.py`、`repair_evidence.py`、`requirement_routes.py`、`evidence_projection.py`。

### 3. 在隔离分支中做完一轮修复

- 编码器可在同一候选工作树发起有界的源码检查、增量编辑或声明验收。检查绑定冻结验收 ID 和真实 Git 内容树；简单任务仍可直接返回终结式编辑。
- 先重验当前待修检查，再在原额度内接续分叉点已知失败的其他行为项，按验收 ID 去重。普通断言修好但旧行为退化时，下一条请求就能看到退化，不必等外层拒绝再开分支。
- 同一节点的失败记忆保留分叉点、被拒树以及原生结果；切换节点时不夹带其他节点的被拒补丁。历史不当作当前树通过，内环和外层的原生结果均按各自版本保存。
- 同执行、同规格、同基线已拒绝的精确候选可直接剪枝；两棵不同树重复失败且没有新证据时及时止损。环境故障与未执行验收有独立状态，不作为改代码的诊断。
- 当前失败路径可定位当前源码；不变的工作树保留定位，编辑或重基改变内容树后不沿用旧的执行结论。公开路径结果用精简格式记录，减少重复描述，不丢收据。

主要文件：`coding_worker.py`、`worker_checks.py`、`worker_factory.py`、`branch_repair.py`、`orchestrator.py`、`source_context.py`。

### 4. 从候选主干到真正交付

- DAG 节点按能独立验收的产物拆分，依赖写入冻结计划；并发合并后在新基线重新门禁。先保留局部通过的候选，再判断完整目标，必要时运行策略规定的签批和独立复核。
- 拒绝分支不会推进目标 Git 分支。最终快进绑定原目标分支和精确提交；目标正被当前工作树检出时一并同步文件，不覆盖冲突的本地修改。
- 运行状态、目标审计、独立复核和 Git 发布是不同事实。查询用相配的请求/完成收据识别已发布；收据不足或冲突时明确显示对应状态。

主要文件：`delivery_evidence.py`、`goal_audit.py`、`independent_validation.py`、`git_sandbox.py`、`app.py`。

## 与此前三个开发包逐版对照

| 对照包 | 该版本已交付的重点 | 本包在它之上的差异 |
| --- | --- | --- |
| **源码定位版（focus）** | 重试先定位原主干未满足的行为；同一内容树的只读操作保留首次焦点。 | 补上外层拒绝收据回传、历史摘录压缩、按节点接续、增量编辑即时验收、完整路径反馈及两路检查合并；新增对话工作台。 |
| **修复收据版（receipts）** | 隔离分支被外层门禁拒绝时回传精准路径收据；上下文压力下优先保留分叉点证据。 | 切换修复节点不带其他节点补丁；增量编辑即时判定新旧行为；把逐路径反馈压成可完整归档的结果；普通检查和分叉点检查同时存在时均可按原额度重验；新增对话工作台。 |
| **增量即时验收版（native）** | 已有按节点续修、同分支即时验收、完整路径精简输出。 | 补齐普通检查与冻结行为检查并存时的重验，避免先跑普通检查挤掉另一项；前端换成对话入口、左侧历史、分面证据、可收起检查器和新版 DAG。 |

以上三包以实际存档的源码 ZIP 为准，不按文件日期或 Python 包版本号推断区别。提交包外层的 `DIFF-三版本.md` 列出每个基线相对本包的精确增删改与源码摘要；`Daedalus-main-to-latest.patch` 仅对应现有 `Daedalus-main` 基线。

## 已验证的使用路径

- 浏览器验证过「发送 → 澄清 → 查看规划 → 确认 → Git 交付」，并从历史记录回到摘要、选择 DAG 节点、展开门禁及审计详情。桌面与窄屏均实际检查；执行使用本地脚本化响应，不需要线上模型作为发布验证前提。
- 隔离分支回归验证过新行为已修复、旧行为退化的场景。下一条请求收到正确候选树上的逐路径结果，同一分支修正后经完整门禁交付；12 条路径的结果可同时出现在请求和持久记录中。
- 如何安装、绑定验收及启动界面见 [README](../README.md#快速开始)；可按时间和专题查阅[完整变更记录](../CHANGELOG.md)。
