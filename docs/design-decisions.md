# 设计决策与实现边界

本文说明 Daedalus 当前实现中的关键取舍，以及与 v2.1 规格文字需要区分的地方。它不是验收报告，也不替代源码、持久化契约或部署安全评审。整体结构见[架构](architecture.md)，剩余工作见[路线图](roadmap.md)。

## 1. 模型提供候选，控制面决定状态

**选择**：规划、编码与语义审查共用受限模型协议，输出必须通过确定性解析、规格校验和边界检查。合法状态迁移只由 FSM 声明，经应用服务记录事件及投影。

**理由**：将模型内容与权限分开，避免一段模型文本同时承担计划、授权和审计结论。

**边界**：确定性控制流程不代表模型输出确定，也不代表验收标准完整。Tier-2 是有失败关闭规则的语义判断，不是形式化证明；Tier-1 失败不能被模型同意覆盖。

实现：[状态机](../src/daedalus/domain/fsm.py)、[迁移服务](../src/daedalus/application/fsm_service.py)、[门禁流水线](../src/daedalus/application/gatekeeper/pipeline.py)。

## 2. SQL 收据原子化，Git 副作用受限对账

**选择**：将步骤提交事件、状态、制品元数据、门禁引用、租约释放、后继基线和幂等结果放在同一 SQLite 事务。Git 提交与 ref 更新在数据库之外，由独立对账逻辑处理收据缺口。

**理由**：Git 与 SQLite 没有共同事务。把数据库事务写成“同时回滚 Git”会隐藏真实崩溃窗口。

**边界**：对账只承认已经存在、精确匹配审查主体和明确提交意图的事实；不运行 Worker、不新建提交、不重基、不更新 ref。目标分支尚未发布时，恢复不会自行完成发布。重基、人工 override 和不完整旧记录仍可能需要人工处理。

实现：[原子收据](../src/daedalus/application/fsm_service.py)、[提交对账](../src/daedalus/application/commit_recovery.py)。

## 3. 并发执行，串行集成

**选择**：独立步骤在各自 worktree 中并发实现；控制面串行处理门禁与运行分支集成。整个运行满足交付条件后，才将目标分支快进到获批提交。

**理由**：保留独立节点的并行能力，同时避免部分成功被误认为整轮目标已经完成。

**边界**：重基会改变审查主体，必须重新生成制品并过门禁；不能用旧批准覆盖新树。单机仓库锁协调控制器与修复操作，但不提供分布式 Worker 调度或分布式一致性。

实现：[编排器](../src/daedalus/application/orchestrator.py)、[工作区池](../src/daedalus/application/worktree_pool.py)、[仓库锁](../src/daedalus/infrastructure/repository_lock.py)。

## 4. 节点级缓存身份与整份规格身份分开

**选择**：复用键中的规格摘要使用节点主体，而非整份 bundle 摘要；同时要求代码基线、依赖、工具链和输入制品匹配，来源已提交且可归因到批准门禁。

**理由**：完整 bundle 包含其他节点的定义，直接用作缓存身份会使不相关的计划变化也失效所有节点，不利于局部重放。

**边界**：节点摘要只解决复用身份，不替代执行归属、整份冻结规格或批准校验。实际提交仍要存在并满足集成前提。变化分类和受影响闭包已实现，但不意味着任意规格变化都有自动失效子图执行入口。

实现：[制品缓存](../src/daedalus/application/artifact_cache.py)、[重放与变化分类](../src/daedalus/application/replay.py)。

## 5. 低风险确定性推进与语义批准分开披露

**选择**：无 reviewer 的 LOW/NORMAL 步骤可以在 Tier-1 通过后推进；高风险缺少 reviewer 时升级。模型任务可配置语义审查，`CRITICAL` 即使得到模型同意也不得自动合入。

**理由**：允许离线、脚本化和低风险开发任务使用确定性控制面，而不把“没有模型”包装成“模型已审查”。

**边界**：记录必须披露跳过 Tier-2。整轮仅通过可执行验收时使用 `acceptance_only`，不能将其表述为自然语言目标已获语义确认。开发模式便利不授予高风险或生产发布资格。

实现：[门禁组合策略](../src/daedalus/application/gatekeeper/pipeline.py)、[目标审计](../src/daedalus/application/goal_audit.py)。

## 6. 修复候选不等于盲目重试

**选择**：实现允许确定性验收失败后，将具体反馈交给有界的新候选尝试；这与规格中“不自动重试确定性测试失败”的字面口径存在区别。边界、权限、摘要等不可重试失败仍立即升级。

整轮目标偏离使用版本化修复 stage，包含首次最多三轮，区别于单步尝试次数。Goal、Boundary、Meta-Spec 不放宽，累计预算不重置，高风险修复计划需要新的签批。编码 Worker 在不同尝试反复产生相同无效编辑，且源码树与观察证据未变时，以不可重试的 `worker_no_progress` 停止。

**理由**：同一失败结果本身不会改变；有意义的重试应产生新的修复候选或利用新证据，而不是重复消耗模型调用。

**边界**：尝试上限不保证修复成功；中断后的目标 stage 不自动重开，人工恢复也不能绕过原边界或获得无限预算。

实现：[调度器](../src/daedalus/application/scheduler.py)、[目标 stage](../src/daedalus/application/goal_audit.py)、[编码 Worker](../src/daedalus/application/coding_worker.py)。

## 7. HMAC 审批是共享密钥认证

**选择**：使用用途隔离的 HMAC-SHA256 验证规格批准、步骤决定和交付复核，并记录主体、角色、方案及核验结果。审批服务从工作区推导身份策略，避免调用方漏传登记表关闭控制。

**理由**：在可信控制面前提下，阻止不持有审批密钥的模型、Worker 或普通候选内容伪造批准。

**边界**：HMAC 不提供非对称签名的第三方不可否认性，控制面持有验证所需的共享密钥。无登记且未强制身份的开发工作区允许明确标为未核验的审批；一旦登记或策略要求身份，撤销最后一个主体也不能关闭核验。审核记录不能被解释为实际人员独立性的证明。

实现：[身份与签名服务](../src/daedalus/application/identity.py)、[规格审批](../src/daedalus/application/spec_approval.py)、[步骤审批](../src/daedalus/application/approvals.py)。

## 8. 步骤门禁、目标审计和独立复核各有职责

**选择**：步骤门禁审查单步候选，目标审计核对集成结果与原始目标；策略要求时，独立交付复核在精确待交付提交的干净工作区重做原始验收，并由不同身份和密钥签署报告。

**理由**：所有步骤各自合规，并不必然意味着整体满足目标。另一批准主体的签署也应绑定实际验证结果，而不是只批准一个任务名称。

**边界**：服务新任务默认对 HIGH/CRITICAL 启用独立复核，但不追溯改写旧运行策略。复核仍在同一可信控制器执行，不是独立硬件或外部验证系统；不能替代 `CRITICAL` 步骤批准，也不重置目标修复轮次。

实现：[目标审计](../src/daedalus/application/goal_audit.py)、[独立交付复核](../src/daedalus/application/independent_validation.py)。

## 9. 探测隔离能力，不以配置名称承诺能力

**选择**：按实际可用性和 Boundary 策略选择 host-process、Seatbelt 或 container；显式请求不可用的级别时拒绝，不静默降级。

**理由**：worktree 解决代码工作区分离，不自动解决命令读取宿主文件、联网或消耗宿主资源的问题。

**边界**：host-process 没有内核级进程、文件系统或网络隔离；Seatbelt 不保证宿主读取保密，也不支持域名 allowlist；容器可用性与参数检查不是部署环境逃逸防护验收。部分 rlimit 和进程组清理不能表述为完整任务配额或任意强杀后的孤儿清理。

实现：[驱动契约](../src/daedalus/infrastructure/sandbox/base.py)、[选择策略](../src/daedalus/infrastructure/sandbox/probe.py)、[子进程管理](../src/daedalus/infrastructure/process.py)。

## 10. 依赖字节完整性与运行环境可信度分开

**选择**：对受支持的 Python 声明执行离线哈希锁、缓存、wheel 元数据、RECORD 及传递依赖校验；不在校验器中下载、安装或执行依赖。

**理由**：先确定候选依赖是否对应操作员提供的字节，再讨论执行环境与供应链风险，避免在“验证”时执行不可信安装代码。

**边界**：哈希不证明发布者身份、无漏洞或运行时安装一致性。非 Python 生态、动态声明和未支持锁格式不能因为有 manifest/lock 配对就被当作完整校验通过。详见[依赖完整性](dependency-integrity.md)。

实现：[离线校验器](../src/daedalus/application/dependencies.py)。

## 11. 服务恢复与任务恢复分离

**选择**：停止服务以协作信号在步骤批次边界停车，启动后仅生成未完成任务提醒。恢复审查读取当前证据；只有显式恢复才可能继续任务。

**理由**：服务管理器为了可用性重新启动进程，不应等同于重新授权模型工作、消费预算或发布提交。

**边界**：提醒和恢复审查本身不执行任务，也不修复权威状态；强杀不等于已保存正常检查点，缺失证据仍需对账或人工处理。详见[服务控制](service-control.md)。

实现：[服务生命周期](../src/daedalus/application/service_lifecycle.py)、[恢复入口](../src/daedalus/application/resume.py)。

## 12. 功能存在不等于生产就绪

**选择**：production 发布门禁要求必需项齐全且全部 PASS；development 只提供诊断口径。运行期安全证据和依赖运行环境证据尚未实现完整验收，当前检查明确为 SKIP。

**理由**：跳过、警告和缺少部署证据不能被平均成“通过”。审计评分也只汇总已留下的证据，不决定代码正确或能否上线。

**边界**：当前不能声称 production 门禁通过、系统适合无人值守交付，或隔离与供应链风险已经闭合。部署方仍需按实际环境完成安全与恢复验收。

实现：[发布门禁](../src/daedalus/application/release_gate.py)、[只读证据评分](../src/daedalus/application/scoring.py)。

## 13. 拒绝候选与交付主干分别诊断（2026-10-30）

**选择**：交付评分仍只评价实际候选主干；调查拒绝原因时另行重建摘要一致的失败补丁，并明确标为离线诊断。后续失败事件保留候选树身份，重试传递完整的有界失败依据，已有冻结行为收据按需求与用例细分展示。

**理由**：主干未晋升时，其失败分数不能证明每个被拒补丁都错误。公共回归可能在缺陷基线上已经通过；粗粒度通过分数和丢失的审查推演都不能可靠指导下一次修改。

**边界**：离线通过不触发晋升、不改写封存成绩。仍称独立评估的运行不能将隐藏验收回灌模型；旧题显式转为开发回归后，可以另行冻结原用例供修复使用，但不得再称隐藏评估或改写旧成绩，也不提供金标准实现。简单源码调用关系用于补充证据，不自动推翻语义拒绝；离线模型夹具只证明流程，不证明真实模型交付率。

## 14. 问题关闭需要原题交付证据（2026-10-30）

**选择**：原始实验收据与持续的问题台账分开维护。旧失败可产生多次明确关联的开发修复；每次保留输入、历史、候选、实际验收和交付结果。软件回归通过、模型补丁生成或实验执行完成均不能关闭问题。

**理由**：只封存失败并不断换新题，会失去“原问题是否已解决”的证据。只保存事件但只向 Worker 提供最新一次失败，也会丢掉先前已发现的约束；把审查猜测当作事实同样会误导后续修复。

**边界**：同题修复证明该题在所记版本上的结果，不证明泛化或自主交付率提高。已修复开发用例需要在后续变动后复验；没有实际交付收据的旧问题继续保持未解决，不以测试总数或新的样本分数替代。
