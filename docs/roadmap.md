# Daedalus 路线图

本文区分当前已有实现、仍需补齐的工程能力和部署验收要求，不以历史测试数量、演示结果或模型输出作为完成标记。当前定位是**可信仓库中的受监督工程执行工具**，不是已经通过生产验收的无人值守交付系统。

设计原则：先保障边界、可恢复性和交付证据，再扩大自动化权限；不以自演进或更复杂的模型流程替代基础安全工作。

## 1. 当前已实现的能力

| 能力 | 当前实现 | 适用边界 |
| --- | --- | --- |
| 冻结契约 | Goal、DAG Plan、Boundary、Meta-Spec 校验、摘要及版本关系 | 摘要绑定内容，不证明身份或目标定义正确 |
| 状态与事件 | 显式 FSM、事件追加、状态投影、序号检查、幂等收据 | 依赖可信存储及控制面，不抵抗恶意管理员篡改 |
| 调度与执行 | 依赖就绪检查、租约、过期处理、有界重试、并发 Worker 与失败传播 | 单机控制器协调，非分布式调度 |
| Git 集成 | 步骤 worktree、运行集成分支、快进更新、重基后重新门禁 | 步骤成功不等于整轮目标可发布；不以强推解决冲突 |
| 模型角色 | 规划、编码、语义审查及多供应商适配 | 模型只返回候选，调用成功不保证任务正确 |
| 模型预算 | 按尝试计量、运行累计、并发请求原子预留、显式恢复重建用量 | 本地准入约束，不是供应商账单硬上限 |
| 步骤门禁 | 确定性检查优先，语义审查只收紧，异常升级停车 | 已配置验收未必覆盖全部需求，模型审查不是证明 |
| 整轮目标审计 | 原始验收重做、逐项语义核对、有界修复 stage、精确提交交付 | 仅可执行验收通过标为 `acceptance_only`；中断 stage 不隐式重开 |
| 人工审批 | 风险分级、身份登记、用途隔离 HMAC、制品绑定的步骤决定 | 共享密钥认证，不提供第三方不可否认性 |
| 独立交付复核 | 干净工作区复验、不同身份及密钥签署、证据与提交绑定 | 同一可信控制器执行，不证明人员或硬件真正独立 |
| 恢复与审计 | SQL 原子收据、受限 Git/SQL 对账、检查点审查、备份恢复、审计导出 | 对账不执行新工作、不推进 ref，不覆盖任意崩溃窗口 |
| 服务控制 | 终端与网页操作、本地管理、协作停止、启动提醒、显式任务恢复 | 服务重启不会自动恢复模型任务 |
| 工作台 | 任务澄清、规格复核、执行详情、差异及证据视图 | 界面评分不是正确率或上线许可 |
| 模型连接管理 | 角色配置、远端发送确认、连接测试、临时凭证及 macOS Keychain 安全保存 | 凭证保存依赖平台能力；不将密钥写入公开配置 |
| 按需检索 | 只读源码工具、关键词/代码/向量召回、融合与受控精排 | 向量后端和模型资产需单独配置；检索不增加执行权限 |
| 依赖离线完整性 | 受支持 Python 声明、精确哈希锁、内容缓存、wheel/传递依赖检查 | 不下载、不安装，不证明实际安装环境、发布者或漏洞状态 |
| 冻结行为用例 | 显式本机需求核对 API、基线收据、冻结用例与新任务绑定 | 当前依赖 Seatbelt，网页 intake 和未绑定收据的入口不自动接入 |

实现入口：[规格](../src/daedalus/domain/spec.py)、[编排器](../src/daedalus/application/orchestrator.py)、[门禁](../src/daedalus/application/gatekeeper/pipeline.py)、[目标审计](../src/daedalus/application/goal_audit.py)、[提交对账](../src/daedalus/application/commit_recovery.py)。完整职责见[架构](architecture.md)。

## 2. 优先补齐：部署安全与发布前提

### 2.1 运行期隔离验收

**已有**：host-process、macOS Seatbelt、container 驱动，能力探测、明确拒绝不可用级别、部分资源限制、超时及所属进程组清理。

**缺口**：

- host-process 不提供内核级网络、文件系统或进程隔离，不适合据此宣称安全执行任意不可信仓库。
- Seatbelt 的写限制与禁网不等于宿主文件读取保密；域名级运行期网络 allowlist 尚未闭合。
- 容器可用性探测和参数检查不能替代逃逸防护、挂载与权限边界、运行期禁网的目标环境验收。
- 任务级总内存、CPU 使用率、总磁盘、强杀后的孤儿进程/容器回收仍缺完整约束与部署证据。

**完成标准**：让安全验收绑定实际驱动、运行时、镜像与部署配置，检查有效约束及明确拒绝路径，而不是只检查参数存在。任何环境能力不足都继续明确拒绝或披露，不默认为满足。

实现入口：[隔离选择](../src/daedalus/infrastructure/sandbox/probe.py)、[子进程管理](../src/daedalus/infrastructure/process.py)。

### 2.2 依赖运行环境与供应链

**已有**：离线校验器将锁定声明与操作员提供的内容缓存对应，拒绝不支持或不完整的输入。

**缺口**：实际沙箱安装环境与获验制品的绑定、发布者来源和漏洞证据未形成完整闭环；其他生态与未支持锁格式也不能按 Python 校验能力推定已覆盖。

**完成标准**：将实际执行所使用的依赖、解释器和环境绑定到可核查的已验制品，并明确来源与漏洞策略。新增格式必须有自己的解析和失败关闭契约，不以文件配对替代完整性验证。

参见[依赖完整性](dependency-integrity.md)及[校验实现](../src/daedalus/application/dependencies.py)。

### 2.3 生产发布门禁

[发布门禁](../src/daedalus/application/release_gate.py) 已要求 production 的必需检查齐全且全部 PASS。当前 `runtime_security_evidence` 与 `dependency_runtime_evidence` 仍固定为 SKIP，**production 会被阻断**。development 结果不授予生产资格。

后续必须用可执行、部署绑定的真实验收替换这两项缺口，不能删除必需项、将 SKIP 改写成 PASS，或用离线行为检查代替运行期安全证据。公开源码可用与生产就绪是两个不同状态。

## 3. 优先补齐：恢复覆盖与可控交付

### 3.1 扩展恢复协议，而非扩大隐式重试

**已有**：提交收据事务、明确提交意图、受限已集成提交对账、已发布交付补记、单机仓库锁和人工检查点审查。显式恢复沿用冻结策略与已记录预算，不自动重跑已提交步骤。

**缺口**：重基与人工 override 的待提交状态、跨目标 stage 的中断，以及证据不完整的旧记录，尚不能普遍自动恢复。正常协作停车也不代表强杀后具有同样检查点。

**完成标准**：逐种故障窗口定义可恢复主体、前置证据、拒绝条件与人工处置方式。恢复只能承认已发生事实，不能凭投影猜测批准、制造新提交或默默发布目标分支。

实现入口：[提交恢复](../src/daedalus/application/commit_recovery.py)、[恢复服务](../src/daedalus/application/recovery.py)、[任务恢复](../src/daedalus/application/resume.py)。操作边界见[运行手册](runbook.md)与[服务控制](service-control.md)。

### 3.2 规格变化后的增量执行

**已有**：目标、局部 Plan 与 Boundary 变化分类，下游失效闭包，节点级缓存身份，按提交重放与可归因制品复用。

**缺口**：`plan_selective_replay` 仍是计划计算能力；任意规格变化后自动仅调度失效子图的通用入口尚未接通。不能把 `STALE` 标记或缓存命中视为完整增量执行。

**完成标准**：入口冻结新规格与执行身份，明确可复用节点、必重跑节点及依赖关系；所有复用仍满足五路摘要、提交可用性和门禁来源要求，不重开旧终态。

实现入口：[重放规划](../src/daedalus/application/replay.py)、[缓存](../src/daedalus/application/artifact_cache.py)。

### 3.3 审批认证与真正独立的复核

**已有**：按风险的身份及角色校验、用途隔离 HMAC、职责分离的独立签署、精确提交与有效期检查。

**缺口**：HMAC 不提供非对称签名的第三方不可否认性；不同登记身份和密钥不证明实际人员不同。同一控制器上的干净工作区复验也不是外部独立验证。

**后续方向**：在有明确部署需求时设计非对称签名、密钥轮换与撤销语义、外部验证主体及证据接入。切换认证方案必须显式记录方案与验证状态，不能改变历史审批含义。

实现入口：[身份服务](../src/daedalus/application/identity.py)、[独立复核](../src/daedalus/application/independent_validation.py)。

## 4. 改进任务定义与证据质量

### 4.1 冻结行为用例的统一入口

**已有**：[需求证据服务](../src/daedalus/application/requirement_evidence.py) 可将操作员冻结用例、需求映射、干净基线及边界绑定到收据；新任务可显式携带收据，在步骤和最终目标审计中执行同一用例。诊断结论不新增 FSM 状态，也不自动批准任务。

**缺口**：网页 intake、未绑定收据的旧入口尚未自动采用该流程；现有 API 依赖本机显式操作与可用 Seatbelt。受控执行观察不能证明用例覆盖全部需求或对抗任意 Python 内省攻击。

**完成标准**：让操作员在适用入口清楚看到需求、基线差异、用例归属和未澄清项；集成时保持原范围和冻结用例不可被候选替换，不能把已有收据默认套用到新目标或新基线。

### 4.2 编码与审查上下文

**已有**：编码侧只读观察工具、按需检索、语义审查关联源码上下文、逐项目标证据及重复无进展停止规则。

**缺口**：工具或检索后端可调用，并不证明证据足以支撑判断。审查误报、漏报、上下文遗漏及验收覆盖不足仍需持续控制，不能通过放宽边界或降低证据要求解决。

**完成标准**：结论引用实际观察、命令收据与精确代码主体；证据不足时保留不确定性和人工出口。向量模型及精排的引入必须有清楚的适用条件与不可用提示，不默认宣称优于直接源码搜索。

参见[按需检索](agentic-rag.md)、[检索策略](retrieval-strategy.md)、[目标审计实现](../src/daedalus/application/goal_audit.py)。

## 5. 后置能力

以下能力不应先于上述安全与恢复前提扩大权限：

- **分布式 Worker 与跨主机协调**：当前单机仓库锁、租约和工作区模型不能直接当作分布式协议；需要独立定义身份、隔离、制品传输和故障语义。
- **Canary 与分阶段发布**：目标分支快进不是运行环境渐进发布，当前不能据此宣称已支持线上回滚或流量治理。
- **自演进**：当前保持 Meta-Spec 的自修改禁止项。自动规划、编码、测试或生成变更建议，不等于系统可以自行替换控制面、Gatekeeper、网络、权限或密钥规则。

## 6. 使用与维护约定

- 从源码安装和配置；入门参见[项目说明](../README.md)，配置与运行参见[运行手册](runbook.md)。
- 选取可信仓库、最小可写范围和明确可执行验收，保留人工复核与处置责任。
- 将“功能实现”“隔离可用”“任务验收通过”“部署安全验收通过”分别报告，不合并成一个完成标签。
- 不以脚本化示例证明真实模型能力，不以审计评分证明改动正确，不以发布诊断替代生产门禁。
- 变更控制路径时同步维护事件、恢复、审批和交付契约；设计取舍见[设计决策](design-decisions.md)。
