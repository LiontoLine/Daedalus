# Daedalus 路线图

本文区分当前已有实现、仍需补齐的工程能力和部署验收要求，不以历史测试数量、演示结果或模型输出作为完成标记。当前定位是**可信仓库中的受监督工程执行工具**，不是已经通过生产验收的无人值守交付系统。

设计原则：先保障边界、可恢复性和交付证据，再扩大自动化权限；不以自演进或更复杂的模型流程替代基础安全工作。

## 1. 当前已实现的能力

| 能力 | 当前实现 | 适用边界 |
| --- | --- | --- |
| 冻结契约 | Goal、DAG Plan、Boundary、Meta-Spec 校验、摘要及版本关系 | 摘要绑定内容，不证明身份或目标定义正确 |
| 状态与事件 | 显式 FSM、事件追加、状态投影、序号检查、幂等收据 | 依赖可信存储及控制面，不抵抗恶意管理员篡改 |
| 调度与执行 | 依赖就绪检查、租约、过期处理、有界重试、并发 Worker 与失败传播 | 单机控制器协调，非分布式调度 |
| Git 集成 | 步骤 worktree、运行集成分支、快进更新、重基后重新门禁 | 步骤成功不等于整轮目标可发布；不以强推解决冲突 |
| 模型角色 | 规划、编码、语义审查及多供应商适配 | 模型只返回候选，调用成功不保证任务正确 |
| 模型预算 | 按尝试计量、运行累计、并发请求原子预留、显式恢复重建用量 | 本地准入约束，不是供应商账单硬上限 |
| 工程执行内环 | 共用 Worker 构造、当前树观察、编辑/冻结检查/诊断续调、有界工作状态与证据记录 | 只返回候选；不扩大 shell、规格或审批权限，尚不证明自主任务收益 |
| 步骤门禁 | 确定性检查优先，语义审查只收紧，异常升级停车 | 已配置验收未必覆盖全部需求，模型审查不是证明 |
| 整轮目标审计 | 原始验收重做、逐项语义核对、有界修复 stage、精确提交交付 | 仅可执行验收通过标为 `acceptance_only`；中断 stage 不隐式重开 |
| 人工审批 | 风险分级、身份登记、用途隔离 HMAC、制品绑定的步骤决定 | 共享密钥认证，不提供第三方不可否认性 |
| 独立交付复核 | 干净工作区复验、不同身份及密钥签署、证据与提交绑定 | 同一可信控制器执行，不证明人员或硬件真正独立 |
| 恢复与审计 | SQL 原子收据、受限 Git/SQL 对账、检查点审查、备份恢复、审计导出 | 对账不执行新工作、不推进 ref，不覆盖任意崩溃窗口 |
| 服务控制 | 终端与网页操作、本地管理、协作停止、启动提醒、显式任务恢复 | 服务重启不会自动恢复模型任务 |
| 工作台 | 任务澄清、规格复核、执行详情、差异及证据视图 | 界面评分不是正确率或上线许可 |
| 模型连接管理 | 角色配置、远端发送确认、连接测试、临时凭证及 macOS Keychain 安全保存 | 凭证保存依赖平台能力；不将密钥写入公开配置 |
| 按需检索 | 只读源码工具、关键词/代码/向量召回、融合与受控精排 | 向量后端和模型资产需单独配置；检索不增加执行权限 |
| 依赖离线完整性 | 受支持 Python 声明、精确哈希锁、内容缓存、wheel/传递依赖检查 | 不下载、不安装，不证明实际安装环境、发布者或漏洞状态 |
| 冻结行为用例 | 显式本机需求核对 API、基线收据、网页/CLI/API 绑定 | 需可用 Seatbelt 且须显式选择；不是外部盲验或对恶意代码的保密沙箱 |

实现入口：[规格](../src/daedalus/domain/spec.py)、[编排器](../src/daedalus/application/orchestrator.py)、[门禁](../src/daedalus/application/gatekeeper/pipeline.py)、[目标审计](../src/daedalus/application/goal_audit.py)、[提交对账](../src/daedalus/application/commit_recovery.py)。完整职责见[架构](architecture.md)。

## 2. 优先补齐：部署安全与发布前提

### 2.1 运行期隔离验收

**已有**：host-process、macOS Seatbelt、container 驱动，能力探测、明确拒绝不可用级别、部分资源限制、超时及所属进程组清理。

**缺口**：

- host-process 不提供内核级网络、文件系统或进程隔离，不适合据此宣称安全执行任意不可信仓库。
- Seatbelt 的写限制与禁网不等于宿主文件读取保密；域名级运行期网络 allowlist 尚未闭合。
- 容器可用性探测和参数检查不能替代逃逸防护、挂载与权限边界、运行期禁网的目标环境验收。
- 任务级总内存、CPU 使用率、总磁盘、强杀后的孤儿进程/容器回收仍缺完整约束与部署证据。

**完成标准**：让安全验收绑定实际驱动、运行时、镜像与部署配置，检查有效约束及明确拒绝路径，而不是只检查参数存在。任何环境能力不足都继续明确拒绝或披露，不默认为满足。

本机实际验证了 Seatbelt 写出限制、禁网和进程组清理。临时 Colima 从校验过的镜像启动，Docker 原生六项检查覆盖挂载、只读根、非 root、禁网、内存/PID 限制和正常超时清理；已停止临时实例。尚没有生产配置或控制器强杀后回收证据。

实现入口：[隔离选择](../src/daedalus/infrastructure/sandbox/probe.py)、[子进程管理](../src/daedalus/infrastructure/process.py)。

### 2.2 依赖运行环境与供应链

**已有**：离线校验器将锁定声明与操作员提供的内容缓存对应，拒绝不支持或不完整的输入。
本机独立实验已把 19 个锁定 wheel 与全新断网 venv 的文件及 CLI 启动绑定；OSV 点时查询 18 个第三方版本未返回通告。两项都不替代生产环境、发布者签名或完整漏洞证据。

**缺口**：实际沙箱安装环境与获验制品的绑定、发布者来源和漏洞证据未形成完整闭环；其他生态与未支持锁格式也不能按 Python 校验能力推定已覆盖。

**完成标准**：将实际执行所使用的依赖、解释器和环境绑定到可核查的已验制品，并明确来源与漏洞策略。新增格式必须有自己的解析和失败关闭契约，不以文件配对替代完整性验证。

参见[依赖完整性](dependency-integrity.md)及[校验实现](../src/daedalus/application/dependencies.py)。

### 2.3 生产发布门禁

[发布门禁](../src/daedalus/application/release_gate.py) 已要求 production 的必需检查齐全且全部 PASS。当前 `runtime_security_evidence` 与 `dependency_runtime_evidence` 仍固定为 SKIP，**production 会被阻断**。development 结果不授予生产资格。

后续必须用可执行、部署绑定的真实验收替换这两项缺口，不能删除必需项、将 SKIP 改写成 PASS，或用离线行为检查代替运行期安全证据。公开源码可用与生产就绪是两个不同状态。

## 3. 优先补齐：恢复覆盖与可控交付

### 3.1 扩展恢复协议，而非扩大隐式重试

**已有**：提交收据事务、明确提交意图、受限已集成提交对账、已发布交付补记、单机仓库锁和人工检查点审查。显式恢复沿用冻结策略与已记录预算，不自动重跑已提交步骤。
最终审计完成并批准、尚未记录交付请求的断点，可在人工核对当前检查点后发布已批准的同一集成提交；规格、执行与集成 ref 漂移会拒绝。
运行详情和工作台分开展示审计、独立复核、Git 交付：后者必须有匹配的请求与完成收据；标明提交不代表当前分支未变化。

**缺口**：重基与人工覆盖的待提交状态、未完成目标审计或修复阶段、证据不完整的旧记录，仍不能普遍续跑。正常协作停车也不代表强杀后具有同样检查点。

**完成标准**：逐种故障窗口定义可恢复主体、前置证据、拒绝条件与人工处置方式。恢复只能承认已发生事实，不能凭投影猜测批准、制造新提交或默默发布目标分支。

实现入口：[提交恢复](../src/daedalus/application/commit_recovery.py)、[恢复服务](../src/daedalus/application/recovery.py)、[任务恢复](../src/daedalus/application/resume.py)。操作边界见[运行手册](runbook.md)与[服务控制](service-control.md)。

### 3.2 规格变化后的增量执行

**已有**：目标、局部 Plan 与 Boundary 变化分类，下游失效闭包，节点级缓存身份和可归因制品复用。`POST /api/runs/{id}/replay` 可指定已注册完整 `spec_digest`，只把未失效节点交给原缓存证据校验；命不中时仍实际执行。
同规格、同仓库、同起点的显式失败重放可把父执行的真实验收失败或审查假设送入首轮编码；节点实际基线也必须相同。新规格的选择性重放仍遵守制品缓存校验，不直接混用旧失败上下文。

**缺口**：跨任意崩溃窗口的自动续跑、跨任务经验沉淀，以及可随规格增量更新的交付基线仍需验证。重放不会覆盖已发布的分叉历史；不能把计划标记或缓存命中当作发布成功。

**完成标准**：入口冻结新规格与执行身份，明确可复用节点、必重跑节点及依赖关系；所有复用仍满足五路摘要、提交可用性和门禁来源要求，不重开旧终态。

实现入口：[重放规划](../src/daedalus/application/replay.py)、[缓存](../src/daedalus/application/artifact_cache.py)。

### 3.3 审批认证与真正独立的复核

**已有**：按风险的身份及角色校验、用途隔离 HMAC、职责分离的独立签署、精确提交与有效期检查。

**缺口**：HMAC 不提供非对称签名的第三方不可否认性；不同登记身份和密钥不证明实际人员不同。同一控制器上的干净工作区复验也不是外部独立验证。

**后续方向**：在有明确部署需求时设计非对称签名、密钥轮换与撤销语义、外部验证主体及证据接入。切换认证方案必须显式记录方案与验证状态，不能改变历史审批含义。

实现入口：[身份服务](../src/daedalus/application/identity.py)、[独立复核](../src/daedalus/application/independent_validation.py)。

## 4. 改进任务定义与证据质量

### 4.1 冻结行为用例的统一入口

**已有**：[需求证据服务](../src/daedalus/application/requirement_evidence.py) 将操作员冻结用例、需求映射、干净基线和边界绑定到 READY 收据。网页预览、CLI 和直接 API 可显式绑定；启动前复查基线；多节点在集成树验收。模型只见公开需求、结果与收据。
对跨步骤任务，可冻结用户入口 → 状态变化 → 可观察结果，并将变更、保留路径绑定到同一基线的真实检查。网页、CLI 和任务 API 可以显式要求这种收据；没有路径证据不算通过。入口校验不替代操作员审查测试是否真的覆盖路径，也不替代外部封存验收。

**缺口**：现有 API 依赖本机显式操作与可用 Seatbelt。没有收据的运行不获得这层验收；即便绑定也不能证明用例覆盖全部需求或防止恶意 Python 内省。收货汇总已按显式收据协议通过未改动的原盲验；原失败成绩仍保留。`16950` 的原封存验证仍未形成自主交付。

**完成标准**：让操作员在适用入口清楚看到需求、基线差异、用例归属和未澄清项；集成时保持原范围和冻结用例不可被候选替换，不能把已有收据默认套用到新目标或新基线。

### 4.2 编码与审查上下文

**已有**：编码侧只读观察工具、按需检索、语义审查关联源码上下文、逐项目标证据及重复无进展停止规则。

**缺口**：工具或检索后端可调用，并不证明证据足以支撑判断。审查误报、漏报、上下文遗漏及验收覆盖不足仍需持续控制，不能通过放宽边界或降低证据要求解决。

**完成标准**：结论引用实际观察、命令收据与精确代码主体；证据不足时保留不确定性和人工出口。向量模型及精排的引入必须有清楚的适用条件与不可用提示，不默认宣称优于直接源码搜索。

参见[按需检索](agentic-rag.md)、[检索策略](retrieval-strategy.md)、[目标审计实现](../src/daedalus/application/goal_audit.py)。

### 4.3 自主工程能力主线

工程能力改进与部署验收分别推进，不通过放宽既有边界换取交付率。

- **本阶段已接通**：服务、CLI、回放和实验共用 Worker 工厂；实验显式消融；同一候选中的读源、编辑、声明验证和修复循环；当前内容树快照；原生检查收据及无进展保护。简单任务仍保留终结式编辑快路径。
- **基本任务规划**：生成计划以可独立验收的产物为最小单位，显式记录依赖；独立分支并行，耦合修改保留单步。局部验收不能决定整题交付；最终目标检查不再人为制造编码节点。基础盲验 DAG 形状 3/3、外部行为 2/3；收货汇总随后以公开需求衍生收据试跑一次，真实交付且通过原盲验，不改写冷启动成绩。轻量 DAG 的重基复审仍有可测开销。见[本轮证据](../CHANGELOG.md#本轮证据与仍开放项)和[独立实验守则](../AGENTS.md#blind-experiments)。
- **固定旧题结果验收已接入**：从原始源码和冻结开发验收运行无封存补丁、无操作员诊断计划的求解回归，保存实际模型请求、版本清单、失败、交付及完整用量；与人工辅助产物回归、配置诊断和真正未见题分开报告，原成绩不改写。脚本为显式付费的本机研究入口，不成为普通安装依赖。
- **P2 工程机制**：有界工具观察跨尝试续接、执行/假设/环境分流、历史 traceback 的当前消费者导航、限定符号与独立匹配窗口、冻结预期归属解释及拒绝目标分支的结构化上下文。真实执行失败后的终结式编辑自动接入原额度内的冻结重验，工具拒绝不再直接丢弃候选；机制存在不等于模型已自主解决旧题，逐题是否闭环以实际收据为准。
- **本阶段结果与未闭环项**：`14122`、`13551` 的保留自主合格交付原提交通过复验，不能与最近完整三题 cohort 1/3 合并。`16950` 的公开问题描述重放 6 次调用、25,447 token，仍未交付：前两轮相同补丁因观察收据不同而被重复审查，第三轮新补丁破坏原生回归。已阻止同一主体重复审查；动作协议和重复防护的回归通过不是原题通过。
- **公开行为契约对照**：`16950` 增加经独立作者按公开描述冻结并预检的反例，同样未交付（7 次调用、39,356 token）。一个候选同时破坏已有回归并遗漏新要求；另一个恢复回归却未满足新要求，随后再次生成已失败的树。停止后原盲验未收到交付提交，不追加无变化的付费重试。
- **同规格失败重放**：`16950` 的首条实际模型请求携带父执行证据，并通过封存目录读保护检查。3 次调用、16,643 token，重复失败树停止，未交付。新修复在原检查/字符额度内保留历史 traceback 锚点并在首步读当前公开消费者；该路径已由真实 native 失败、重放、实际发布的工程专项覆盖。
- **约束对照与候选剪枝**：实际首条请求确认历史结果没有冒充当前树结果。`16950` 同题复跑 8 次、47,124 token，仍未交付。外层第一轮旧回归通过但新行为未满足；下一轮优先重验新行为仍失败，最终到达原预算准入上限。保留原盲验和失败记录，下一变量应是区分新旧行为的推理方法，不是加预算或上下文。
- **推理模式单变量对照**：原 `16950` 的同 wheel、同冻结规格、同预算协议中，仅给 DeepSeek Flash 编码请求开启低档推理；零派发预检确认消息、模型和输出上限未变。5 次调用、48,722 token，3 次输出截断，零编辑；原非思考对照 8 次、47,124 token，也未交付。推理占输出 token 的 21,667/21,806，瓶颈先变成无法返回可执行编辑，不能据此判断更强模型能否解题。保持现有默认配置；后续先验证一条短且可证伪的新旧行为区分能否指导兼容编辑，不放大 token 上限。
- **配对编辑雏形**：用独立原生探针验证失败早停、保留项退化拒绝、兼容候选实际 Git 交付三个路径。固定 `16950` 配对实验中 Flash/Pro 均未交付；Pro 暴露增量编辑未即时验证的缺口，现有独立开发回归已验证增量编辑在下一次模型请求前取得同树证据，尚无原题闭环。
- **原题增量反馈复验**：Pro 在同规格、同模型、同预算的新包上产生两个不同的增量候选，待修检查都在当时的树上执行并失败；未得到可交付候选。此前该路径零检查，现已能在下一步前反馈，但本次支出从 40,843 到 46,669 token，不能算提效。下一步应先离线验证能提供不同且可证伪的代码假设，再决定是否付费复跑。
- **离线因果对照与盲验恢复**：`16950` 的直接表单集与完整 Admin GET→POST 不能互相替代。人工辅助候选分离展示初值与模型字段值，通过公开往返及原冻结验收，实际发布到隔离分支。修复通用原生监督器的解释器参数和工作树路径后，原封存盲验完整运行 7 项但未通过。保留该候选及失败，不更改原题或用例，不计入自主交付。
- **公开兼容复验**：原题公开对照扩展到程序化调用者复用、真实主键及已保存对象的关联拒绝；新候选覆盖 4/4，旧人工辅助候选为 3/4。原冻结验收及实际发布通过，原封存 7 项完整验收仍未通过。公开矩阵唯一定义了选出的候选；下一步不应把封存失败当成修改提示或靠继续试提交刷分。
- **不同树重复失败**：两次真实同类失败后，编辑需要当前树的新源码证据；未观察到新证据则不再写入。脚本化原生探针验证了无证据停机、有证据继续和单步快路径，未重跑原封存题，不主张自主正确率收益。
- **控制面开销**：目标审计复用同一候选快照的诊断；独立离线对照保持诊断与候选语义指纹一致。实际隔离分支请求只带一份同样的修复反馈。未测供应商 token 或整任务完成时间，不能据此推导合格交付效率。
- **仍需补强**：跨节点与共享代码的真实责任发现、审查疑点的针对性证伪，以及长期任务状态的授权复用。归属解释不能在冻结契约有歧义时推断真实所有者，不得把冻结预期误称为完整理解需求。
- **尚未实现的后续阶段**：稳定项目身份、经验证的跨任务经验/技能提炼，以及按有效性条件复用独立检查。当前有界工作观察和修复记忆不等于上述能力，不默认引入向量记忆库或更多审查角色。

核心指标为自主合格交付率、固定原题闭环率、计入失败与检索/审查的每次合格交付总 token/耗时，以及经实际复核的误拒和重复重试。控制面回归、脚本化 HTTP 决策与真实原生执行各自提供不同证据，不能合并成模型准确率成绩。


## 5. 后置能力

以下能力不应先于上述安全与恢复前提扩大权限：

- **分布式 Worker 与跨主机协调**：当前单机仓库锁、租约和工作区模型不能直接当作分布式协议；需要独立定义身份、隔离、制品传输和故障语义。
- **Canary 与分阶段发布**：目标分支快进不是运行环境渐进发布，当前不能据此宣称已支持线上回滚或流量治理。
- **自演进**：当前保持 Meta-Spec 的自修改禁止项。自动规划、编码、测试或生成变更建议，不等于系统可以自行替换控制面、Gatekeeper、网络、权限或密钥规则。

## 6. 使用与维护约定

- 从源码安装和配置；入门参见[项目说明](../README.md)，配置与运行参见[运行手册](runbook.md)。
- 选取可信仓库、最小可写范围和明确可执行验收，保留人工复核与处置责任。
- 将“功能实现”“隔离可用”“任务验收通过”“部署安全验收通过”分别报告，不合并成一个完成标签。
- 不以脚本化示例证明真实模型能力，不以审计评分证明改动正确，不以发布诊断替代生产门禁。
- 变更控制路径时同步维护事件、恢复、审批和交付契约；设计取舍见[设计决策](design-decisions.md)。
