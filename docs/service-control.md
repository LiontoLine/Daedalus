# 服务启动、停止与人工恢复

本指南介绍终端控制台、托管后端、启动提醒和中断任务恢复。源码安装、部署边界、审批与备份见[运维手册](runbook.md)。

**启动服务不等于继续任务。** 打开网页、保存提醒、重新启动后端或恢复模型连接，都不会自动排队执行中断任务。

## 1. 启动与配置

完成源码安装并激活虚拟环境后：

```bash
daedalus
```

命令启动或连接托管后端，进入 `daedalus>` 交互控制台并显示启动提醒。需要同时打开网页：

```bash
daedalus --open
```

首次使用无参数入口时，会在当前用户的数据目录创建持久配置与工作区，默认监听 `127.0.0.1:13499`。实现也会优先复用该数据目录下已有的兼容配置；这不是对任何机器安装状态的承诺。

如需固定配置，建议明确指定，后续启停始终使用同一个文件：

```bash
daedalus --config "$CONFIG" --open
```

`CONFIG` 应事先设置为已有配置文件的绝对路径。普通 `daedalus init` 配置的服务默认端口是 `13475`，与无参数入口创建的配置不同；以当前配置和实际显示的地址为准。工作区不会自动搬迁，也不会自动合并其他数据库。不要把日常工作区放在可能被系统清理的临时目录。

## 2. 日常控制

| 控制台输入 | 操作 |
| --- | --- |
| `/start` | 启动托管后端，不继续中断任务。 |
| `/stop` | 请求安全停车、保存断点并关闭。 |
| `/restart` | 保存断点后重启后端。 |
| `/status`、`/tasks`、`/reminders` | 查看后端状态、任务与启动提醒。 |
| `/review 任务ID` | 查看当前断点并保存人工审查，不执行任务。 |
| `/resume 任务ID` | 明确请求继续已审查的任务。 |
| `/open` | 打开网页工作区。 |
| Ctrl+C、Ctrl+D、`/quit` | 请求保存断点，关闭托管后端并退出终端控制台。 |
| `/detach` | 退出终端控制台，后端保持原状态。 |

网页顶部「服务」也可填写下次开启时的提醒，并选择「保存断点并关闭」或「保存断点并重启」。网页关闭不等于服务关闭；后端停止后，网页本身不能再启动它，应从终端使用 `daedalus` 或 `service start`。

不进入交互控制台时：

```bash
daedalus service start --config "$CONFIG" --open
daedalus service status --config "$CONFIG"
daedalus service stop --config "$CONFIG"
daedalus service restart --config "$CONFIG"
```

`daedalus serve --config "$CONFIG"` 是前台后端入口，不经过上述管理进程，没有其网页重启能力。由外部服务管理器托管时，应通过该管理器控制生命周期，避免双重管理。

### 同端口重启与旧实例

从系统终端执行：

```bash
daedalus --config "$CONFIG" --restart --open
```

若仍在 `daedalus>` 中，先 `/detach` 返回系统终端，或直接使用 `/restart`。重启保持原端口，不自动换一个端口来绕过占用。

普通管理流程控制自己启动的后端。显式停止或重启还可识别同一用户的旧 Daedalus：核对监听 PID、进程身份和 API，留存仍可读取的任务与审计视图，再请求正常关闭。端口属于其他程序或身份不符时，不发送关闭信号。

旧实例交接会尝试备份；如果只能读取 API 视图，这些视图只是人工审查材料，不能当作完整数据库备份。新旧工作区不同时不会合并历史。替代实例无法监听时不会为了“腾位置”盲目关闭旧实例；等待旧进程退出超时不会强杀或同时开启第二个实例。

## 3. 正常关闭会发生什么

1. 停止接收新的工程工作，不把原有排队任务当作关闭流程的一部分执行。
2. 等待当前步骤批次通过原有门禁与提交边界，未完成运行在安全边界停车。
3. 保存停止备注、未完成任务列表及会话状态；需要时生成经过一致性检查的数据库断点副本。
4. 关闭后端。重启后只显示提醒，等待人工审查与明确继续。

这不是立即中断承诺。模型请求、测试进程或 Git 提交正在进行时，可能需要等待；状态显示正在保存时应检查日志并等待，不以强杀代替正常停止。已经提交的步骤保持原有提交和回执，不会因为重启被改回可执行状态。

工作区内的管理资料：

| 位置 | 用途 |
| --- | --- |
| `.service/session.json` | 会话状态、停止备注与启动提醒。 |
| `.service/checkpoints/<session_id>.sqlite` | 有未完成任务等情况下，从活跃数据库连接生成的断点副本。 |
| `.service/service.log` | 托管后端日志。 |
| `.service/controller.json`、`.service/request.json` | 管理进程状态与启停请求。 |

这些记录不替代权威事件日志、Git 数据、门禁证据或签批。管理状态含有本地控制令牌，相关 JSON 文件采用受限权限；不要复制到公开问题、聊天或仓库。提醒和审查备注也不应包含任何密钥。

断点副本只作为恢复材料，启动时不会自动还原。强制结束进程、宿主崩溃或断电可能来不及保存最后一份副本；此前已提交的持久证据仍需逐项核对。

## 4. 重新开启后如何继续

在「上次会话提醒」中打开「查看断点并人工审查」，核对：

- 停止原因、上次提醒和未完成任务是否符合预期；
- 原仓库、集成分支及已保留的提交是否仍可用；
- 已验证节点、待续节点与依赖关系；
- 是否存在未完成执行、提交对账或目标审计 / 修复阶段的阻断。

| 动作 | 结果 |
| --- | --- |
| 仅保存审查备注 | 记录对当前断点的人工审查，任务保持停止。 |
| 审查并继续任务 | 记录审查，并明确排队继续；仍须满足原规格、预算、门禁及审批要求。 |

恢复审查绑定运行、execution、规格摘要、集成提交、步骤状态与已有证据。审查后这些事实改变，就必须重新查看和审查；恢复时还会在仓库锁内核对。保存一个通用“同意恢复”备注不能永久授权后续状态。

启用 Owner 身份核验时，审查必须沿用有效身份、角色权限和签名；未启用时仅记录未核验的人工操作。访问登录口令不是 Owner 签名，恢复审查也不替代高风险规格批准、步骤批准或独立交付复核。

模型连接可能通过系统钥匙串恢复，也可能需要重新配置临时连接，取决于保存方式和平台支持，见[凭证存储说明](model-credential-storage.md)。**连接恢复不会自动恢复任务。**

### CLI 与 API 恢复

可从 UI 查看断点，也可在已获访问授权的会话中读取 `GET /api/runs/{run_id}/recovery`。确认当前断点后，尚未启用身份核验的工作区可显式保存审查并继续：

```bash
daedalus resume --config "$CONFIG" --run-id "$RUN_ID" \
  --reviewed-by operator \
  --review-note "已核对原有提交、当前证据与待续节点"
```

`RUN_ID` 来自实际任务记录。该命令不是预览：通过审查与前置条件后会尝试继续执行。若只想保存审查，不继续任务，应使用 UI「仅保存审查备注」或终端 `/review`。

已启用身份核验时，还需有效的 `--signature`。恢复接口的 `review_statement_digest` 是带恢复用途的签名主体，`checkpoint_digest` 用来核对审查对应的当前断点；不要直接把普通规格签名或旧断点签名当作恢复签名。交互终端 `/review` 可使用登记身份对应的可信环境密钥完成签署，不需要将密钥写入命令行。

### 恢复被阻断时

不要修改数据库状态、删除工作树或重置受管 Git 引用来消除提示。先保存现场，按[运维手册](runbook.md)使用 `recover` 查看报告，必要时在停止相关写入后执行恢复对账，再重新审查。

目标审计或修复阶段已有历史时，恢复可能要求专门的人工核对或经审查的新任务；重启不会清空阶段迭代预算。无法证明安全的状态保持停止，不会因为再次点击继续而跳过检查。

## 5. 访问设置与登录自启

### 本机和私有局域网访问

默认只监听回环地址，不要求登录。在受信任本机浏览器打开网页「访问设置」（`/auth/setup`），先设置独立访问口令，再选择启用本机登录或私有局域网访问。不要把口令放进 URL、Shell 命令或配置文件。

非回环监听必须启用登录且已有访问口令，否则启动拒绝。该机制面向单操作员的本机 / 私有局域网，不提供多用户角色隔离或 TLS；不能据此公开暴露服务。跨设备访问还需要受控网络、加密链路及防火墙，并应单独评估代理对来源判断的影响。

### macOS 登录自启与故障拉起

网页「访问设置」可启用当前用户的 LaunchAgent。此功能仅支持 macOS 用户会话，不代表系统级守护进程已经安装，也不保证任何主机上的启用结果；以页面状态和错误提示为准。

托管交接会先启动并预检替代监督进程，再请求原管理进程释放工作区。故障拉起针对服务进程，不自动继续工程任务；正常停止不因失败重启策略立即复活。登录自启项仍保留，后续登录可能再次启动服务，但任务仍需人工审查。

登录自启的进程不保证继承交互 Shell 中的凭证环境。使用已支持的安全保存方式，或通过可信进程管理环境供应凭证，不要将密钥硬编码到启动项。移动源码、虚拟环境或配置后，应重新核对启动入口及工作目录。
